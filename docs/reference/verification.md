## 1. 环境与证据边界

通过 ADB 操作真实 App，读取屏幕、可访问性层级、Room 数据库及私有照片文件；没有假的识别器、预置停车记录、在线接口或按图片注入的车牌答案。

| 环境 | 实际 ABI / 页大小证据 | 用途与限制 |
| --- | --- | --- |
| API 24 AOSP 模拟器 | x86_64；进程辅助向量 `AT_PAGESZ=4096` | 最低版本安装、完整 Android 回归、200% 字体 / 横竖屏、权限、旋转、升级与 guest 重启、结束清理 |
| API 36 AOSP 模拟器 | x86_64；4096 字节 | 完整 Android 回归、生产模型批量推理、实际业务闭环与错误注入 |
| API 35 Google APIs 16KB 模式 | `getconf PAGE_SIZE` 和 `/proc/self/auxv` 均报告 16384；系统 ABI 为 `x86_64,arm64-v8a`，`libndk_translation.so` | 强制安装的包 `primaryCpuAbi=arm64-v8a`；执行 ARM64 Debug 回归及未修改生产 keep 规则的 R8 包 JNI / UI。ARM64 指令经翻译执行，**不代替原生 ARM64 手机或原生 ARM64 16KB 验收** |
| 直接启动 ARM64 / ARMv7 镜像 | 当前 Intel 主机的 Emulator 37.2.13 实际拒绝启动 | ARM64 提示系统镜像必须匹配宿主架构；ARMv7 提示 QEMU2 不支持 `arm`、classic engine 已弃用。不把下载 / 构建成功算成运行通过 |

界面宽 320dp。CameraX 拍到的是模拟器室内场景；未检出时在同一弹窗填写测试车牌，验证登记与照片生命周期，**不冒充实车正检拍照**。真实车牌正检另由生产 `PlateRecognizer` / JNI / 随包模型运行，R8 探针也调用真实 ARM64 JNI。车牌样本不在用户 APK 的 `assets/plates/` 中。

坚果 Pro 3 和 Redmi Note 14 Pro 5G（天玑 7300-Ultra）均未连接。两台的 ROM / Android、实际 ABI、内存、页大小、对焦 / 方向、速度与持续运行表现仍未读取，不用规格页或模拟器替代。

### 2.1 真实公开挑战照片

[原始 CCPD](https://github.com/detectRecog/CCPD) 明确声明数据集 MIT。蓝牌取自 [固定镜像版本的 CCPD2019 train.zip](https://huggingface.co/datasets/okita-souji/ccpd2019train/blob/230a8d1092b7c8b0113541efe9861527275b5c04/train.zip)，绿牌取自 [固定镜像版本的 CCPD2020.zip](https://huggingface.co/datasets/htkien95/ccpd2020/blob/be503e89159f5e92a5306260b76b82a324d15a34/CCPD2020.zip)。使用相应公开镜像范围下载，解析 ZIP / ZIP64，校验每张 JPEG 的 CRC32、解码和 SHA-256；**没有下载完整归档，因此未重算完整归档 SHA-256**。

每类固定取路径字典序最前 30 张，不按识别结果挑图。两类均为 720 × 1160 全图；保留文件名原始标注并查看放大的车牌裁片，部分图低清 / 模糊，不能声称全部都可无争议独立读出。文件名带面积字段，排序偏向小车牌，蓝牌来自训练目录；模型训练数据未知。**这是固定挑战集检查，不是随机样本、未见集证明或可泛化准确率。**

| 类别 | 张数 | 整牌正确 | 错误 | 未检出 | 热调用数 | 热 P50 ms | 热 P95 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 蓝牌 | 30 | 26 | 4 | 0 | 30 | 905.196 | 1289.928 |
| 新能源绿牌 | 30 | 11 | 16 | 3 | 29 | 909.913 | 1290.898 |

P50 为中位数，P95 为 nearest-rank；绿牌首张包含冷引擎初始化且未检出，耗时 1963.294ms，已从热统计剔除。模型此前已复制，**不是全新安装冷启动耗时**。测量发生于 API 36 x86_64 Debug，不能套用于两台手机、ARM64 Release 或产品时延承诺。

蓝牌错误编号为 01 / 11 / 19 / 27。绿牌正确编号为 12 / 15 / 18 / 19 / 20 / 21 / 22 / 25 / 27 / 28 / 30，未检出为 01 / 05 / 14，其余错误；省份混淆和暗光颜色误判均保留，没有改真值、隐藏失败、自动猜省份或补入固定数字。

## 3. 实际业务链路与本轮修复

### 3.1 已保留的停车闭环证据

- 2026-10-31 首次拍照 `23:15:13`，约 82 秒后确认，首页显示 `00:01:22`；从最终编辑值 `AD12346` 登记，不从确认时归零。
- 重复登记使照片由原图加草稿两张回到原图一张；数据库整行、起点、标识及原图 SHA-256 不变。结束后同牌再停车生成新标识和照片，旧历史不变。
- 首页返回桌面、强停重开、锁屏、guest 真正重启后记录 / 照片仍在；重启后明确显示估算。结束弹窗等待至少 83 秒后，保存的结束时刻落在最终点击边界，而非弹窗打开时刻。
- 在停按开始时间升序，历史按结束时间倒序；实际搜索 / 详情可用，历史无照片和结束入口。结束一辆车不删另一辆车的照片。
- 重拍从 `23:42:54` 更换为 `23:43:36` 的新锚点 / 新文件；取消不新增记录，其他在停照片保持原 SHA-256。MediaStore 对实际车辆照片名查询无结果。
- 模型副本可逆读权限故障使 native 真正初始化失败，弹窗明确“离线识别失败”，不回显路径、不冒充正常未检出；恢复权限及相同 SHA 后可重拍恢复。

### 3.2 2026-11-02 新增实跑与修复

1. **绿牌贪心漏字：** 保留 `苏ED51712` 真值，改用通用有界 CTC 解码；修复词典与张量类别数不同导致的拒绝 / 越界风险，以及 MNN 分数略大于 1 被错误拒绝。原蓝 / 绿断言均通过，未换通道或训练权重。
2. **旋转丢草稿：** CameraScreen 不再把 composition 销毁当作用户取消；保留拒绝权限的请求历史，重新绑定时重置 ready。API 24 实际拍照后编辑 `AD24001`，横竖屏旋转仍保留照片、输入和原始时间；确认后的显示已含等待时间。
3. **大字与键盘：** 相机 / 权限页可滚动，取景高度有界；确认 / 返回 / 重拍主动结束输入，首页初次进入不自动打开搜索键盘。API 24 / 36 实际检查 200% 字体、横竖屏、弹窗滚动与键盘。API 24 的系统权限弹窗在 200% 横屏时有系统布局限制，转回竖屏授权可用，不将系统弹窗说成已修复。
4. **升级和重启：** API 24 已存 `AD24001` 在升级安装及 guest boot count 1 → 2 后，原行与照片 SHA 完全不变，详情显示“重启后按系统时间估算”；最终历史保存 `durationMs=2073849`、`WALL_CLOCK_ESTIMATE`，照片和删除任务均归零。
5. **真实 UI 结束保存失败：** 仅在自建模拟器实际数据库中临时安装拒绝历史写入的 SQLite trigger；点击最终确认后显示“结束记录保存失败，原停车记录和照片均保留”。在停、完整历史、待删任务和原照片 SHA 均未改变；触发器已撤销。
6. **清理失败 / 快速恢复：** 只对自建模拟器照片目录临时撤销写权限，结束事务成功、历史落盘、照片 / 删除任务仍在，UI 如实提示未完成。实际复现快速 Home → App 只有 `RESUME`、没有 App 的 `STOP`，旧 `STARTED` 入口漏重试。修复为 `ON_RESUME` 后，同场景照片 / 任务归零，过期警告消失；采用通知实例身份比较，避免恢复任务清掉较晚的新消息。
7. **拍照写入失败：** 同样以目录权限模拟真实 CameraX 文件 I/O 失败，页面显示“无法保存照片，请检查剩余空间后重试”，没有半条在停或残留 JPEG。恢复目录权限后重新拍照 / 识别 / 弹窗 / 取消均可用；不是已证明真实满盘或所有 OEM 存储故障。

所有权限均已恢复，故障触发器与临时探针已撤销。业务验证最终在停、车辆照片和待删任务均为零，历史只留在测试设备运行数据中；用户 APK 不含测试停车数据。截图、层级、SQLite / 照片快照在 `.tooling/ui-proof/`，不是预制 UI 模板。

照片位于 `no_backup/parking_media/`，不进相册。最终 manifest 只有相机及 AndroidX 自有签名权限，没有 INTERNET；`allowBackup=false`，两代规则排除数据库 / WAL / SHM、照片、设置和标准迁移。未承诺 OEM 特权迁移或闪存取证级安全擦除。
