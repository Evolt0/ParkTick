# ParkTick 停车计时 App 需求文档

- 文档类型：产品需求文档（PRD）
- 更新日期：2026-11-02
- 阶段：原生 Android 源码、可安装 APK 和主要业务回归已完成；仍处于实施验证阶段，目标双机、原生 ARM / 16KB 与完整三类样本验收尚未关闭，不作为正式验收完成版本。
- 确认状态：当前已讨论的业务需求、全局易用性基线及页面与弹窗交互均已确认；识别与设备验证前置条件见第 9 节。
- 项目称呼：沿用当前项目目录名 ParkTick，不代表已另行确认中文产品名称。

## 1. 背景与目标

开发一款 Android App，供使用者在一台手机上管理多辆车的停车记录。通过拍照离线识别车牌，以拍照时刻为停车开始时间；车辆离开时，由使用者在列表中手动结束停车，保存本次停车时长。

核心目标：

- 拍照登记车辆，减少手动输入车牌的工作。
- 同时查看多辆在停车辆的停车时长。
- 全程离线使用，照片和停车数据仅保存在本机。
- 停车结束后保留时间记录，删除车辆照片。

## 2. 已确认的产品范围

| 项目 | 要求 |
| --- | --- |
| 平台 | Android |
| 使用方式 | 单台手机管理多辆车 |
| 实际使用机型 | 坚果 Pro 3、Redmi Note 14 Pro 5G（天玑 7300-Ultra），均纳入必测；两台分别独立保存本地数据 |
| 网络 | 核心识别、登记、计时、结束停车和记录查询均不依赖网络 |
| 数据位置 | 仅保存在本机，不上传车辆照片和停车记录 |
| 车牌识别范围 | 大陆常见蓝牌、普通黄牌、新能源车牌 |
| 开始方式 | 拍照后弹窗确认车牌，允许直接修改后登记 |
| 结束方式 | 在车辆列表中手动结束，操作前二次确认 |
| 照片保留 | 仅在停车期间保留，结束后删除 |
| 历史数据 | 保留车牌、开始时间、结束时间和停车总时长，不保留照片 |

以下能力不在当前范围：账号、服务器、云同步、多人多设备协作、收费、支付、自动识别离场、超时提醒。特殊车牌及港澳、境外车牌不列入本次识别验收范围。

## 3. 已确认的业务规则

### 3.1 计时起点与登记

- 拍照成功时立即记录拍摄时间，以此作为本次停车的开始时间。
- 离线识别、手动修正车牌、确认登记的耗时均计入停车时长，不重置计时起点。
- 拍照识别后，在拍照页弹出“确认车牌”弹窗，将识别结果填入可编辑的车牌输入框。
- 用户在同一弹窗中核对或直接修改车牌，不额外跳转修改页面，也不增加一层确认。
- 只有点击“确认登记”后，才按用户最终确认的车牌检查在停记录，创建新记录或展示已有记录；不能识别成功后自动创建，也不能用修改前的识别结果代替最终车牌。
- 识别失败时，同样显示该弹窗并保留当前照片，提示手动输入车牌或重新拍照。
- 本文的手动输入指拍照后的车牌填写，不额外定义不拍照直接新增的登记方式。
- 重新拍照时，丢弃上一次未登记的照片和时间，改用新照片的拍摄时间。
- 取消登记时，不创建停车记录，并清理本次临时照片。

### 3.2 重复车牌与再次停车

- 同一车牌只能有一条进行中的停车记录。
- 重复登记时，展示该车牌已有的进行中记录，不创建第二条记录。
- 重复登记不得重置原开始时间，不得覆盖原车辆照片；本次重复拍摄产生的临时照片需要清理。
- 上一次停车结束后，再次登记同一车牌时，创建新的独立记录，不覆盖历史记录。

### 3.3 结束停车

- 用户手动触发结束操作后，必须进行二次确认。
- 结束确认弹窗展示车牌和当前停车时长。
- 确认文案为：“确认结束本次停车？结束后将删除车辆照片，保留车牌和停车时间记录。”
- 取消确认时，原记录继续计时，不修改停车状态。
- 以点击最终“确认结束”的时刻作为结束时间，而不是打开弹窗的时刻。
- 确认结束后，先保存结束时间与总时长，再删除车辆照片及相关临时副本。
- 保存结束记录失败时，保留原记录和照片，提示失败，不显示结束成功，不执行照片清理。
- 结束后的记录进入历史，不再属于在停车辆。

### 3.4 照片存储与清理

- 照片保存在应用私有目录，不自动写入系统相册。
- 在停记录保留对应车辆照片，可用于核对车辆。
- 已结束记录不保留照片，包括相关缩略图和临时副本。
- 取消、重拍或重复登记产生的无用临时照片不得作为正式停车照片继续保留。
- 原有在停记录的照片不受其他失败或取消的登记操作影响。

### 3.5 计时持续性

- 退出 App、锁屏或重启手机，不丢失已保存的停车记录。
- 再次打开 App 时，能继续显示在停车辆已经经过的停车时长。
- 不要求 App 常驻后台，不以后台持续运行、每秒累加作为记录存续的前提。
- 进行中的时长依据开始时间和当前时间计算；已结束记录的总时长在结束后固定，不继续增长。

## 4. 页面与交互

### 4.0 全局交互与可读性基线（已确认）

所有页面以“操作简单明了、能明确返回、文字容易看清”为共同设计约束。

#### 操作简单明了

- 每个页面突出当前任务的主要操作，使用直接说明动作的文字，例如“拍照登记”“确认登记”“结束停车”。
- 常用操作直接可见，不依赖长按、隐藏菜单或仅凭图标猜测含义。
- 不为登记和结束停车增加无关步骤或必填信息；保留已经确认的车牌核对和结束前二次确认。
- 返回入口和主要按钮应方便点击，点击区域以不小于 48dp × 48dp 为初始设计基线。

#### 明确的返回按钮

- 所有业务页面在左上角提供清晰可见的“返回”按钮，不仅依赖系统手势或系统返回键。
- 非首页页面返回上一级；首页作为根页面，其返回按钮按 Android 系统返回行为离开应用，不结束停车、不清除记录。
- 页面返回按钮与系统返回的页面导航行为保持一致；结束确认弹窗中的返回按取消处理，不执行结束或删除照片。
- 从车牌确认弹窗返回拍照页，视为放弃当前未确认的照片和车牌填写，清理本次临时照片，不创建正式记录；重新拍照时使用新的拍摄时间。
- 从拍照页返回首页，不创建记录；从停车详情或历史页面返回，不修改已有停车记录。

#### 字体偏大、重点突出

- 初始排版采用正文、输入框和按钮文字约 18sp，车牌及停车时长约 22–24sp；这些数值是设计起点，可根据实机排版微调，整体保持偏大、易读。
- 不为压缩列表而将关键车牌、时间和操作文字缩成小字。
- 支持系统字体缩放；字体放大后，关键文字和按钮不得被裁切、遮挡或重叠，必要时允许换行或滚动。

### 4.1 在停车辆首页（已确认）

- 默认展示正在停车的车辆。
- 按开始时间排序，停得最久的车辆在前。
- 每条记录展示车牌、开始时间、已停时长及“结束停车”按钮。
- 顶部支持按车牌搜索在停车辆。
- “拍照登记”是主要操作入口。
- 点击记录进入停车详情，查看照片和完整停车信息。
- 已结束记录放入独立的“历史记录”页面。

### 4.2 拍照页（已确认）

- 显示相机取景框和拍照按钮。
- 提示使用者将车牌放入取景框。
- 拍照成功时记录拍摄时间，随后执行离线车牌识别。

### 4.3 车牌确认弹窗（已确认）

- 在拍照页上显示标题为“确认车牌”的弹窗，不额外跳转页面。
- 展示本次车辆照片缩略图和拍照时间，便于核对；该时间仍作为停车开始时间。
- 车牌输入框自动填入识别结果，使用醒目、偏大的文字；点击输入框即可直接修改，不另设修改页面。
- 识别失败时，仍使用同一弹窗，允许手动填写车牌或重新拍照，不另开一层错误确认弹窗。
- 提供“确认登记”和“重新拍照”操作，以及明确的“返回”入口；返回和重拍按第 3.1 节清理本次临时照片。
- 点击“确认登记”后按最终车牌执行第 3.2 节的去重规则，不再次弹出登记确认。
- 新记录保存成功后返回首页，从本次照片的拍摄时刻累计显示停车时长；已有在停记录则展示原记录。

### 4.4 停车详情（已确认）

- 展示车牌、车辆照片、开始时间和当前停车时长。

- 页面底部提供“结束停车”按钮，与首页列表入口使用相同的二次确认和结束规则。

### 4.5 历史记录（已确认）

- 提供独立页面，展示已结束的停车记录。
- 按结束时间倒序排列，最近结束的记录在前。
- 每条记录展示车牌、开始时间、结束时间和总时长。
- 支持按车牌搜索历史记录。
- 点击记录查看完整时间信息，不显示照片入口，也不保留照片缩略图。


## 5. 逻辑数据需求

以下仅定义业务数据，不指定数据库、表结构或代码实现。

| 数据项 | 业务含义 |
| --- | --- |
| 记录标识 | 区分同一车牌的不同停车次数 |
| 车牌号码 | 用户最终确认的车牌，用于展示、搜索和在停去重 |
| 停车状态 | 进行中或已结束 |
| 开始时间 | 本次有效照片拍摄成功的时间 |
| 结束时间 | 结束停车时保存；进行中的记录无结束时间 |
| 总时长 | 已结束记录保存的停车总时长；在停时长实时计算 |
| 车辆照片关联 | 在停期间关联本机私有照片，结束清理后不保留照片 |

登记确认前暂存照片及拍摄时间，不将其作为正式停车记录。技术栈、识别路线、数据结构及内部职责见[技术方案](../../design/technical-solution.md)；当前需求不需要服务端 API。

## 6. 离线、隐私与数据可靠性

- 车牌识别必须具备真正的离线能力，不能以在线接口作为正常使用的前提。
- 识别所需资源应支持离线交付，不依赖首次使用联网下载模型或在线授权后才能完成核心操作。
- 不上传照片、车牌和停车记录。
- 本地保存不等于备份：卸载应用、清除应用数据或丢失手机可能导致记录丢失，当前不承诺备份恢复能力。
- 保存结束记录与清理照片有明确先后顺序，不得先删照片再尝试保存结束信息。
- 蓝牌、普通黄牌和新能源车牌均需使用真实样本验证离线识别效果；本文不预先承诺未经实测的识别准确率。

| A-19 | 执行拍照登记、确认登记和结束停车 | 主要操作及文字含义清晰可见，无需长按或进入隐藏菜单；不增加无关步骤，保留必要核对与确认 |
| A-20 | 在首页、拍照、停车详情和历史页面，以及车牌确认弹窗操作返回 | 各页和弹窗均有明确返回入口；弹窗返回拍照页，非首页页面返回上一级，首页按系统行为离开应用；已有停车记录和计时不受影响 |
| A-21 | 从车牌确认弹窗返回拍照页或从拍照页返回首页 | 不创建正式记录，清理放弃的临时照片；再次拍照使用新的拍摄时间，不覆盖其他在停记录 |
| A-22 | 检查初始排版并增大系统字体后使用各页面 | 字体整体偏大，车牌和时长突出；关键文字及按钮不裁切、不遮挡、不重叠，内容可通过换行或滚动完整查看 |
| A-23 | 拍照识别完成，尚未点击“确认登记” | 在拍照页弹出车牌确认弹窗，预填可直接编辑的车牌，展示照片和拍摄时间；此时不创建正式记录，不额外跳转页面 |

## 9. 技术设计与实施前置条件

- [技术方案](../../design/technical-solution.md)已明确 Kotlin、Compose、CameraX、Room，以及固定源码修订后构建的 HyperLPR3 离线识别路线。
- 旧 SDK ARM64 库已核验为 4KB ELF 段对齐，不能直接作为 16KB 兼容制品放行；许可清单、JNI 资源修订、本地初始化、ABI / 16KB 和三类实拍效果必须完成技术方案 G1–G5 门禁。
- 结束记录与照片清理采用事务加可恢复删除任务；正常结束立即清理，中断或删除失败如实提示，在后续运行恢复，不把文件删除与数据库提交说成同一个原子操作。
- 同次开机用单调时钟，跨重启按墙钟估算并标记来源；完全离线且系统时间任意变化时不能保证准确重建真实时长。异常情况不得用伪造时长掩盖，正常退出、锁屏和重启后的记录保留要求不变。
- Android 最低 API 24、compile / target API 36 已写入工程，已完成 Debug 与混淆 Release 构建；实际包体积和可达验证见运行记录。两款目标手机的兼容性、耗时及三类样本识别效果仍待实测，不以 CPU 规格代替结果。
- 已执行工具链、源码构建及可达环境回归，实施状态见[实施计划](implementation-plan.md)。原绿牌漏字精确回归已通过，但挑战照片仍有错误 / 未检出，普通黄牌授权样本库和目标机门禁未关闭；不删减离线识别或照片清理要求，也不把手工补救说成识别效果验收通过。
